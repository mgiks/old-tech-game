# Архитектура прогрессии v2

Игра читает правила из кода и из каталога навыков. Экран дерева только показывает их и вызывает покупку. Старые id (`spawn_rate_1`, `attraction`, `server_access` и остальные) больше не дают эффектов. `SkillTreeDefinition.GetStat` для старого перечисления возвращает 0, чтобы старые компоненты не притягивали файлы и не начисляли вторую награду.

## Где что менять

| Что | Файл |
|---|---|
| Список узлов, максимумы, пороги `P`, требования, координаты | `Assets/Scripts/Progression/Pure/SkillBalanceTable.cs` |
| Формулы эффектов | `Assets/Scripts/Progression/Pure/EffectMath.cs` |
| Цена, базовая награда, защита от переполнения | `Assets/Scripts/Progression/Pure/EconomyMath.cs` |
| Видимость, циклы, достижимость 120 | `Assets/Scripts/Progression/Pure/UnlockEval.cs` |
| Длительность забега, бонус времени, потолок таймера, 3 секунды загрузки, радиус цепи, бюджет цепи 24, скорость мини-вируса, жизнь осколка, радиус потоков | `Assets/Scripts/Progression/Pure/ProgressionConfig.cs` |
| Спавн файлов, стартовое число и потолок стола | `DesktopIconManager` на сцене `Main` (`initialIconCount` 5, `maxIconsOnScreen` 12, `baseSpawnIntervalInSeconds` 0.9) |
| Файлов на компьютер и рост 1.25 | `RunManager` (`baseFilesPerComputer`, `filesPerComputerGrowth`) плюс константы в `ProgressionConfig` |
| Тексты имён и описаний | `Assets/Scripts/Localization/Loc.cs`, ключи `skill.<id>.name` и `skill.<id>.desc` |
| Подписи эффектов в подсказке | `EffectText.cs` и ключи `effect.*` |
| Раскладка на экране | поля `X` и `Y` в `SkillBalanceTable`. `SkillCatalog` переносит их в узлы. Проверка не даёт центрам сблизиться сильнее чем на 170 |

После правки каталога дерево в памяти собирается заново в `SkillTreeDefinition.OnEnable`. Иконки подставляются из уже сохранённого ассета или, в редакторе, из `Assets/Art/Skills`.

## Покупка и сохранение

`SkillTreeDefinition.TryBuy` проверяет доступность. `GameProgress.TrySpendMB` списывает цену. `GameProgress.CommitSkillLevel` поднимает уровень. Если запись не проходит, MB возвращаются через `RefundMB`. `P` — это сумма уровней покупаемых узлов, отдельный счётчик не хранится.

Файл сохранения: `Application.persistentDataPath/progress_v2.json`.

Версия формата: `2` (`ProgressionConfig.SaveVersion`).

Внутри: текущие MB, все заработанные MB, флаг интро, флаг полной победы, пары id и уровня. Неизвестный id пропускается. Уровень режется по максимуму узла. Чужой или битый файл не смешивается с новым деревом: при другой версии или порче он перекладывается в `progress_v2.rejected.json` или `progress_v2.corrupt.json`, а игра стартует с пустым прогрессом.

Главное меню и кнопка «Новая игра» этот файл не стирают. Полный сброс делает только явное «Начать заново» на концовке: `GameProgress.StartOver` удаляет сохранение. Настройки громкости, языка и экрана живут в `PlayerPrefs` и этим сбросом не трогаются.

Запись происходит при покупке, при получении MB, в конце забега и при выходе из приложения.

## Забег

`RunManager` ставит длительность 20 секунд, если в сцене осталось меньшее старое значение. При переходе на следующий компьютер добавляет `computerTimeBonus` (2 секунды) и не даёт остатку превысить `maxRemainingSeconds` (36). Сервер больше не требует отдельного навыка «сетевой червь».

Временное стирается само: файлы уничтожает `ClearDesktop`, мини-вирусы и цепи теряют цели, потому что объекты файлов исчезли. Перегрузка, рывок и синергия живут до конца забега и умирают вместе со сценой. Навык и MB не сбрасываются.

## Одна шкала файла

`DesktopIcon` хранит общий прогресс. В него пишут:

- `FileHoverDownload` — курсор, соседние потоки и буфер после ухода;
- `RunDirector` — мини-вирусы и цепь.

На 100% вклад останавливается, `RunDirector.HandleComplete` выполняется один раз и запоминает источник: Manual, MiniVirus, Chain. Дальше: заряд перегрузки, возможная цепь, выбор «заразить или отдать вирусу», осколки, вспышка и старый полёт файла. Награда начисляется в `ScoreManager.AddFile` только если `TryMarkReward` ещё не срабатывал.

Перетаскивание в вирус больше не добивает недокачанный файл. Оно отдаёт уже скачанный или уже заражённый файл.

Правая кнопка во время наведения ставит желание заразить. Если слотов хватает, файл остаётся на столе.

## Кто за что отвечает в забеге

| Система | Класс |
|---|---|
| Сбор эффектов для геймплея | `GameplayQuery` |
| Мини-вирусы, цепь, перегрузка, пассив, разнос, осколки, синергия, рывок | `RunDirector` |
| Шкала и жест курсора | `FileHoverDownload`, `DesktopIcon` |
| Появление ценных файлов | `DesktopIconManager` |
| Выплата MB за поглощённый файл | `ScoreManager` |
| События без повторного запуска механик | `GameEvents` |

Геймплей не подписывается на свои события, чтобы завершение не вызывало само себя. События поднимаются после изменения состояния.

Старые `VirusAttraction` и `VirusSatellites` в `Update` сразу выходят. Их гравитация и орбитальные копии заменены мини-вирусами.

## Симулятор

`Assets/Scripts/Progression/Pure/BalanceSimulator.cs` не копирует формулы вручную: он вызывает `EconomyMath`, `EffectMath` и `UnlockEval`.

Запуск без Unity:

`dotnet run --project Tools/BalanceRunner/BalanceRunner.csproj -c Release`

Он пишет `Tools/balance-sim-output.txt`.

В редакторе ту же проверку узлов делает `UnlockEval.Validate()`.
